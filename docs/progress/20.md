# Issue #20 — trimming the MCP tool surface

## 2026-08-10 — measurement, no code

`tools/list` as Claude receives it: **55.576 byte ≈ 13.900 token, 31 tool** (description 47%,
inputSchema 48%). Five core loop tools are 40% of that and cannot be cut. Merging the three `kind`
pairs saves 6% and takes 31 → 28, not 20. Full numbers in the issue body.

The measurement that could **not** be taken: which tools are actually used. Container logs since the
2026-08-10 deploy held 12 calls across 5 tools, and they die with the container.

## 2026-08-11 — proposal step 1: make usage countable

Shipped `mcp_tool_call` (one row per tool name), written by `guard()` through an injected recorder,
read on /settings → Tài khoản.

Three decisions worth keeping:

- **A counter, not a call log.** Per-call rows would buy a time series nobody reads and cost unbounded
  growth in a database nobody prunes. `calls` / `errors` / `lastMs` / `lastError` answer both
  questions the table exists for.
- **Errors are counted too**, which turned out to be the bigger win. A throwing MCP tool answers
  HTTP 200 with `isError`, so it is invisible to the client, to `npm run verify`, and to the learner —
  the 2026-08-08 session burned nine graded turns that way, visible only in a log that later
  restarted. `errors` and `lastError` survive a restart.
- **The recorder is injected** (`setToolCallRecorder`), not imported. `guard()` runs in dozens of pure
  unit tests; a hard-wired writer would have each of them upsert into whatever `DATABASE_URL` pointed
  at when the module loaded.

`lastError` took two red e2e runs to get right, and both were the same mistake in different clothes:
guessing the shape of Prisma's message instead of measuring it. Head-truncation stored 400 characters
of Turbopack chunk path; splitting on blank lines assumed a seam that is not there. The sentence is
the last **line**, and only for errors carrying a Prisma `code` — see `errorDigest`.
